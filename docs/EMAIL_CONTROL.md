# Email control

Open **Developer & support portal → Email control** using the master account.

- Preview all 15 current email variants, including plain text, HTML and the sample CSV attachment. Previews use the actual application mail functions with fake names, links, codes and gift data.
- Send one selected template or all templates to the entered test recipient after confirmation. The recipient defaults to the signed-in master address, and every address is validated and checked for opt-out. Test messages have a `[Template preview]` subject prefix.
- SMTP must be configured for inbox delivery. With `MAIL_OUTBOX_DIR`, the response reports files written to the development outbox instead of claiming inbox delivery.
- Search unsubscribed addresses, stop delivery, or restore delivery at a recipient's request. These controls and sample sends are master-only and audited.
- Every outgoing email includes a signed preferences link in plain text, HTML where present, and the `List-Unsubscribe` header. Visiting the page does not change delivery; the recipient must confirm the action. No login is required.
- Opt-out blocks **all** app email to the normalized address, including invitations, recovery messages, advertising alerts and deletion backups. In-app notifications remain available. The preference survives account deletion and covers recipients who have no account.
- Account deletion still requires its previously promised emailed CSV backup. If the address is unsubscribed, the deletion review provides a link to restore email delivery first.
- No background email scheduler is introduced. Invitations and other transactional messages retain their current triggers.

Storage: migration `3f8a12c6d904` adds the `email_suppression` table. Apply with `npm run db:upgrade`. Render's existing Flask pre-deploy migration command applies the same revision.

# HTML block editor

In Email control, choose a template and click **Edit HTML blocks**. Add, remove or reorder HTML blocks; edit their HTML, font, size, text color and background. **Preview changes** renders an unsent sample in a sandboxed frame, with rendered HTML available below it. **Save template** applies the design to future HTML emails; **Restore original template** removes the override.

Exactly one live message block is required. Its codes, action links and recipient details remain generated by the app, rather than saved from preview samples. Its styling is editable, while its generated wording remains controlled by the app. Custom HTML blocks support basic email markup and safe inline styles; unsupported tags, event handlers and unsafe links are stripped. The plain-text alternative remains the original app message. Unsubscribe links are added automatically and CSV attachments stay intact.

Design changes and preview endpoints require a superuser support session. Saved changes are audited. Migration `51a8c29e7b10` adds `email_template_design`; no existing lists or profiles are changed.
